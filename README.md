# Contribuir com a documentação

Agradecemos as contribuições de membros da comunidade e funcionários da Adobe.

## Código de conduta de código aberto da Adobe

Este projeto segue o [Código de conduta do Adobe Open Source](code-of-conduct.md) ou
o [&#x200B; Código de conduta do .NET Foundation](https://dotnetfoundation.org/code-of-conduct).
Para obter mais informações, consulte [Contribuição](contributing.md).

## Como contribuir com o conteúdo da Adobe

Se você não for um funcionário da Adobe, poderá enviar uma contribuição da comunidade. A equipe de documentação analisa as contribuições no repositório público e sincroniza as alterações aprovadas com os sistemas internos da Adobe.

Se você for um funcionário da Adobe, contribua diretamente para o [repositório GitHub privado do Adobe](https://git.corp.adobe.com/AdobeDocs/). Para obter detalhes, consulte o guia de criação da Adobe Experience League para funcionários da Adobe.

## Colaboradores externos

### Pequenas alterações

Se você estiver contribuindo com uma pequena atualização:

1. Vá para o tópico que deseja editar.
1. Na **O conteúdo foi útil?** banner na parte inferior da página, selecione **Opções detalhadas de feedback**.
1. Selecione **Sugerir uma edição** e envie uma solicitação de pull com suas alterações.

   Consulte o [Guia do colaborador do Adobe Docs](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) para obter mais informações.

As pequenas correções ou esclarecimentos que você envia para a documentação e os exemplos de código deste repositório são abrangidos pelos termos de uso da Adobe.

### Grandes alterações e novos tópicos

Para criar um tópico ou propor uma grande alteração, envie um problema da guia **Problemas** no repositório Git apropriado. Um membro da equipe de documentação trabalha com você para chegar a um acordo sobre um plano e publicar a revisão.

>[!NOTE]
>
>Se você enviar documentação significativa ou alterações de código, a solicitação de pull solicitará que você conclua um contrato de licença de colaborador online (CLA). Conclua o CLA antes que a equipe de documentação revise sua solicitação de pull.

### Ferramentas

Use a interface do GitHub para edições básicas. Para contribuições importantes, bifurque o repositório.

Consulte o [guia do colaborador do Adobe Docs](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) para obter mais detalhes.

## Colaboradores internos

Se você for um autor técnico, gerente de programa ou desenvolvedor de produto da Adobe que cria artigos técnicos, use o [repositório privado](https://git.corp.adobe.com/AdobeDocs).

## Formatar seu tópico

Os artigos neste repositório usam o GitHub Flavored Markdown. Para obter ajuda, consulte:

* [Noções básicas sobre o Markdown](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [Folha de características do Markdown para impressão](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## Rótulos

O repositório público atribui rótulos automaticamente para extrair solicitações:

* **Alteração enviada ao autor**: o autor foi notificado da solicitação de pull pendente.
* **pronto para mesclar**: a solicitação de pull está pronta para revisão.
